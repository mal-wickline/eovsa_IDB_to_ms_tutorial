# EOVSA 2024-05-14 X8.8 flare: IDB-to-MS guide

This guide produces one calibrated, full-resolution CASA Measurement Set for the 2024-05-14 X8.8 flare and transfers it from `pipeline` to a Mac.

## Event and input data

- Flare ID: `20240514164700`
- Start: `2024-05-14 16:45:47 UT`
- GOES peak: `16:48:46 UT`
- End: `16:52:58 UT`
- Raw IDB archive: `/nas5/IDB/20240514/`
- Required scans:

  ```text
  IDB20240514163948   approximately 16:39:48–16:49:48 UT
  IDB20240514164948   approximately 16:49:48–16:59:48 UT
  ```

The first scan is essential because the second begins about one minute after the GOES peak.

## Important terminology

A CASA Measurement Set ending in `.ms` is a directory containing many CASA tables, not a single ordinary file. This workflow creates two temporary MS directories, then concatenates them into one logical calibrated MS directory.

## Prerequisites

- Access to `pipeline` and `/nas5/IDB/20240514/`.
- Read credentials for the EOVSA SQL calibration database.
- The maintained pipeline Python environment.
- Adequate space under `/data1/mw478/` for two IDBs, two intermediate MS directories, and the concatenated MS.

Never paste database passwords into a terminal transcript, chat, script, or GitHub repository.

## 2. Produce corrected local IDBs

Load the maintained Python environment:

```bash
source /home/user/.setenv_pyenv38
cd /data1/mw478/selfcal_20240514
ipython
```

In IPython:

```python
import os
import numpy as np

# Compatibility for older EOVSA code when required by the installed NumPy.
if not hasattr(np, "float"):
    np.float = float

from eovsapy import flare_spec as fs

raw_idbs = [
    "/nas5/IDB/20240514/IDB20240514163948",
    "/nas5/IDB/20240514/IDB20240514164948",
]

corrected_idbs = fs.calIDB(raw_idbs)
print(*corrected_idbs, sep="\n")
```

Approve the two listed inputs when prompted. Successful processing should report that calibration was applied and create these local directories:

```text
/data1/mw478/selfcal_20240514/IDB20240514163948
/data1/mw478/selfcal_20240514/IDB20240514164948
```

Do not rely only on the returned list: older versions can return the raw paths after a failure. Verify the local products explicitly:

```python
local_idbs = [
    "/data1/mw478/selfcal_20240514/IDB20240514163948",
    "/data1/mw478/selfcal_20240514/IDB20240514164948",
]

for path in local_idbs:
    print(path, os.path.isdir(path))
```

Both must print `True`, and the log must not contain an SQL failure. Then exit:

```python
exit
```

### Why explicit paths are used

Do not use `fs.calIDB(Time(...))` for this event. Older pipeline environments may lack `EOVSADATE`/`EOVSADB2`, and a lookup beginning at `16:43` selected only the `16:49:48` scan, missing the flare peak. Explicit paths are reproducible.

## 3. Convert the corrected IDBs to intermediate MS directories

The working SunCASA import is isolated from incompatible personal packages with `PYTHONNOUSERSITE=1`:

```bash
source /home/user/.setenv_pyenv38
cd /data1/mw478/selfcal_20240514
PYTHONNOUSERSITE=1 ipython
```

First import the task and allow the initial SunCASA/SunPy/Matplotlib load to finish. It can take several minutes:

```python
from suncasa.suncasatasks import importeovsa
print("importeovsa loaded")
```

Do not interrupt the import unless it produces an actual exception.

Then run:

```python
import os

local_idbs = [
    "/data1/mw478/selfcal_20240514/IDB20240514163948",
    "/data1/mw478/selfcal_20240514/IDB20240514164948",
]

for path in local_idbs:
    if not os.path.isdir(path):
        raise RuntimeError(f"Missing corrected IDB: {path}")

outdir = "/data1/mw478/selfcal_20240514/msdata/"
os.makedirs(outdir, exist_ok=True)

msfiles = importeovsa(
    idbfiles=local_idbs,
    visprefix=outdir,
    ncpu=1,
    timebin="0s",
    width=1,
    doconcat=False,
    udb_corr=False,
)

print(*msfiles, sep="\n")
```

For this event, the conversion took about 1,603 seconds and produced exactly these two intermediate MS directories:

```text
/data1/mw478/selfcal_20240514/msdata/IDB20240514163948.ms
/data1/mw478/selfcal_20240514/msdata/IDB20240514164948.ms
```

Confirm what actually exists before proceeding:

```python
for path in msfiles:
    print(path, os.path.isdir(path))

print(*sorted(os.listdir(outdir)), sep="\n")
```

At this point there is **not yet one combined MS**. Do not try to transfer `IDB20240514_163948-165948.cal.ms` until the next step has successfully created and verified it.

Settings:

- `timebin="0s"` preserves full time resolution.
- `width=1` preserves the input channel resolution.
- `udb_corr=False` prevents double-applying the total-power/attenuation corrections already applied by `fs.calIDB`.
- `doconcat=False` makes two diagnostic intermediate MS directories. The next step combines them.

Do not delete or overwrite an existing output automatically. If a rerun reports that an output exists, inspect the directory first and choose a new run directory or obtain approval for cleanup.

## 4. Apply reference/phase calibration and create one MS

In the same clean IPython session:

```python
from suncasa.suncasatasks import calibeovsa

msfiles = [
    "/data1/mw478/selfcal_20240514/msdata/IDB20240514163948.ms",
    "/data1/mw478/selfcal_20240514/msdata/IDB20240514164948.ms",
]

for path in msfiles:
    if not os.path.isdir(path):
        raise RuntimeError(f"Missing intermediate MS: {path}")

final_name = "IDB20240514_163948-165948.cal.ms"
final_ms = os.path.join(outdir, final_name)

calibrated_result = calibeovsa(
    msfiles,
    doconcat=True,
    concatvis=final_ms,
)

print(calibrated_result)

print("Final MS:", final_ms)
print("Exists:", os.path.isdir(final_ms))
print("All msdata outputs:")
print(*sorted(os.listdir(outdir)), sep="\n")
```

Read the `calibeovsa` output and record:

- the actual observation interval;
- reference-calibration time;
- phase-calibration time;
- warnings about antennas or SPWs; and
- the actual returned/output path.

The pipeline SunCASA version used for this event does **not** accept an `msoutdir` argument in `calibeovsa`; passing it raises `TypeError: __call__() got an unexpected keyword argument 'msoutdir'`. Supply the complete destination through `concatvis=final_ms` instead.

Some SunCASA versions update input MSs in place or return paths differently. Trust the printed task result and verify the filesystem rather than assuming a name. **Do not proceed to transfer unless `os.path.isdir(final_ms)` prints `True`.** If a differently named combined MS is reported, set `final_ms` to that actual path and use that name in all verification and transfer commands.

## 5. Verify the final calibrated MS

Still in IPython:

```python
from casatools import table

if not os.path.isdir(final_ms):
    raise RuntimeError(f"Final concatenated MS was not created: {final_ms}")

tb = table()
tb.open(final_ms)
try:
    columns = tb.colnames()
    nrows = tb.nrows()
finally:
    tb.close()

print("Rows:", nrows)
print("Columns:", columns)

if "CORRECTED_DATA" not in columns:
    raise RuntimeError("CORRECTED_DATA is absent; calibration is incomplete")
```

## 6. Transfer the final MS to the Mac

Run this from the **Mac terminal**, not from pipeline:

```bash
mkdir -p ~/20240514_x8/msdata
```

Use the macOS-compatible, resumable `rsync` command:

```bash
rsync -avP \
  mw478@pipeline:/data1/mw478/selfcal_20240514/msdata/IDB20240514_163948-165948.cal.ms \
  ~/20240514_x8/msdata/
```

Before starting `rsync`, verify the remote source from the Mac:

```bash
ssh mw478@pipeline \
  'ls -ld /data1/mw478/selfcal_20240514/msdata/IDB20240514_163948-165948.cal.ms'
```

Only run `rsync` if that command lists the MS. If it says `No such file or directory`, return to Step 4: either `calibeovsa` has not been run, it failed, or it created a different output name.

Do not use `--info=progress2`; the older `rsync` bundled with macOS does not support it.

Verify locally:

```bash
du -sh ~/20240514_x8/msdata/IDB20240514_163948-165948.cal.ms
```

Compare that size with the pipeline result. Rerunning the same `rsync -avP` command resumes or verifies the transfer.

## Troubleshooting record for this event

### Automatic historical IDB lookup failed

Symptoms included undefined `EOVSADATE`/`EOVSADB2`. The archive mapping showed that 2024 data reside under `/nas5/IDB/`. Explicit paths solved this problem.

### The time lookup omitted the flare-peak scan

The range `16:43–16:55` returned only `IDB20240514164948`, which begins after the GOES peak. Both explicit IDBs are required.

### SQL error 1142

The database account authenticated but initially lacked `SELECT` access to `eOVSA.FV70_VD15`. This required corrected database requirements/permissions; it could not be fixed in the processing script.

### Personal package conflict on pipeline

`~/.local` supplied an internally inconsistent Matplotlib and blocked `suncasa.suncasatasks`. Launching the SunCASA stage with `PYTHONNOUSERSITE=1` selected the maintained site stack.

### `importeovsa` appeared undefined

The name was absent because its import had failed. The first successful SunCASA import may take several minutes; wait unless an exception is printed.

### `rsync` reported `link_stat ... No such file or directory`

This occurred when the two-input `importeovsa` run had completed but `calibeovsa(..., doconcat=True)` had not yet created the proposed singular output. The only existing products were:

```text
IDB20240514163948.ms
IDB20240514164948.ms
```

The fix is not to change `rsync`: first run the concatenating calibration step, inspect its returned path, confirm the final directory with `ls -ld`, and then transfer the exact verified name. An empty `rsync` file list in this situation means nothing was copied and the two remote intermediate MS directories were not damaged.

### `calibeovsa` rejected `msoutdir`

The installed pipeline task reported:

```text
TypeError: __call__() got an unexpected keyword argument 'msoutdir'
```

This happens before calibration or concatenation begins, so the intermediate MS directories remain valid. Use an absolute output path as the `concatvis` value and omit `msoutdir`:

```python
final_ms = os.path.join(outdir, "IDB20240514_163948-165948.cal.ms")
calibrated_result = calibeovsa(
    msfiles,
    doconcat=True,
    concatvis=final_ms,
)
```

### Mac architecture note

The final self-calibration workflow on the Apple-silicon Mac currently uses an x86_64 CASA environment under Rosetta. Check the terminal with `uname -m` before activating that environment. This architecture requirement applies to the current environment, not universally to all CASA versions.
